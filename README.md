# SoL-Astr

给 LLM 一个「压缩上下文」的工具。它自己判断旧话题已经聊完了就调用，工具在 agent 循环内部把早前的对话换成一段摘要，同一轮的续写请求立刻用上压缩后的上下文，轮末由 AstrBot 正常落盘。

移植自 NVIDIA Research [SoL-Pi](https://nvlabs.github.io/SoL-Pi) 的 Online Context Compact：**在语义边界压缩，而不是等上下文快满了才压**。

## 和内置机制的关系

```
[本插件] 语义压缩：LLM 在话题边界自主调用，压缩线按模型价目反推
   ↓ 目标是让上下文尽量到不了 82%
[内置] 82% 压缩：防爆窗兜底，保留，不要关
[内置] 单条工具结果 overflow：正交，不受影响
[核心配置] 按轮截断 max_turns：非 -1 时本插件会告警，但不会替你改
```

## 管理面板

装好之后在插件页打开 **dashboard**，所有东西都在那儿：

- **压缩线是多少、怎么算出来的**，以及模型窗口这个数究竟来自 provider 配置、models.dev、OpenRouter 目录还是兜底值
- **上下文标尺**——把保留段、压缩线、内置 82% 兜底线和各会话的真实用量画在同一根轴上。会话游标全挤在压缩线左边就说明永远触发不了；压缩线贴着兜底线就说明插件来不及先动手
- **模型与价目**——两个模型解析到了 OpenRouter 上的哪一条、四个价格分别多少、这套组合几次请求回本
- **甜点值模拟器**——拖动「目标回本轮数」和「保留段」实时看压缩线怎么变，满意了一键写进配置
- **运行台账**——触发率、outcome 分布、归档段大小分布、每次压缩的前后对比和耗时
- **告警**——三件会让插件悄悄失效的事，下面详述

### 面板会主动检测的三个隐形杀手

这三件事现在只会出现在 error 日志里，没人会去翻：

1. **人格的工具白名单挡住了压缩工具**。人格配了 `tools` 列表却没把 `sol_astr_compact` 加进去，模型根本看不到这个工具，插件完全静默失效。
2. **核心开着按轮截断**（`max_turns != -1`）。它会抢在压缩之前丢掉最老的几轮。
3. **摘要模型贵到永不回本**。见下面的公式——分母 ≤ 0 时压缩这个动作本身就是赔钱的。

## 配置

**摘要模型和压缩提示词不在插件里配**，直接用核心「上下文管理策略」里已有的两项：

| 核心配置项 | 本插件怎么用 |
|---|---|
| 用于上下文压缩的模型提供商 ID | 摘要模型。留空或不可用时回落当前聊天模型，行为与内置压缩器一致 |
| 上下文压缩提示词 | 摘要指令。留空才用插件默认。包裹方式与内置逐字相同，同一条提示词在两边表现一样 |
| 压缩前最多保留对话轮数 | 不是 -1 时插件会告警 |

**压缩模型一定要指一个比主聊天模型便宜、更快的**。摘要是在回复用户之前同步做的，用主模型意味着用户多等十几秒、而且多半永远不回本——面板会直接算给你看。

插件自己的选项（面板里可以直接改）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable_compact` | false | 总开关 |
| `dry_run` | true | 影子模式：只记台账，不调摘要、不改写上下文 |
| `keep_recent_tokens` | 0（自动） | 压缩时按整轮保留的最近上下文 |
| `min_archive_tokens` | 0（自动） | 归档段小于这个数就不压 |
| `target_turns` | 5 | 目标回本轮数，见下 |
| `strip_tool_trace` | true | 压缩成功的那轮，落盘前删掉工具调用记录 |

## 压缩线怎么定的

两个阈值性质完全不同，所以定法也不同：

- **保留段**决定**对话质量**——压完还记得多少原文。价格不该介入，按模型窗口取 `min(窗口×15%, 40000)`。
- **最小归档段**决定**划不划算**——由真实价目反推。

### 由价目反推（默认）

模型名经 OpenRouter 目录解析后拿到真实价目，然后：

```
每轮省 = A × 缓存读价
一次性 = (K+M)(输入价 − 缓存读价) + (K+M)×缓存写价 + A×摘要输入价 + M×摘要输出价

要求 breakeven ≤ N ⇒  A ≥ [(K+M)(Pi−Pc) + (K+M)Pw + M·So] / (N·Pc − Si)
```

`N` 就是 `target_turns`：**这笔一次性投入要求在几次 LLM 请求内赚回来**。注意这里的「轮」是一次 LLM 请求，不是一问一答——模型调一次工具就会产生两次请求，各付一次上下文的钱。压缩后的续写请求本身就算第 1 轮。

N 越大验收越宽松、压缩线越低、压得越早。它的现实含义是「一个话题结束后平均还会再聊几次」，因为压完就冷场的话那笔投入就打水漂了。

**分母 ≤ 0 意味着摘要模型读一遍归档段的钱比 N 轮省下的还多，这套组合永远不回本**——面板会直接报错，而不是让你跑一个月才发现没省钱。

### 价目拿不到时

目录拉不到、或者模型名认不出（私有模型、内部代号），退回按窗口比例：`min(窗口×25%, 60000)`。

纯绝对值在小窗口上是死值（32k 的模型永远够不到 100k 门槛），纯比例在大窗口上等于没压（1M 的 15% 是 150k），取小同时避开两头。

### 窗口这个数从哪来

四级，OpenRouter 插在兜底之前：

1. provider 配置里填的 `max_context_tokens`
2. models.dev 元数据
3. **OpenRouter 目录的 `context_length`**（本插件补的）
4. `fallback_max_tokens`（与模型无关的固定数，拿它当任何模型的窗口都是瞎猜）

第 3 级只在前两级都没有时才补，**只写内存不落盘**，不动你的 `cmd_config.json`。上游会限流，所以目录窗口不作强证据：它只用来定保留段，压缩线由价格决定。

面板上会标明当前这个数究竟来自哪一级。

## 模型怎么知道该压了

压缩由 LLM 自己发起，它需要三样东西：

1. **话题聊完没有** —— 模型自己判断，它擅长这个。
2. **上下文够不够大** —— 模型判断不了。裸给一个「45200 tokens」它无从知道算大算小。**由插件算**。
3. **够大之后干什么** —— 得直说。

插件每轮在用户消息尾部注入一行状态，把 2 和 3 一起给出去：

```
没过线： [context: 当前 45200 / 压缩线 98400 / 模型上限 256000 tokens]

过线了： [context: 当前 105000 / 压缩线 98400 / 模型上限 256000 tokens —— 用量过压缩线了。
        要是刚才那个话题聊完了、也没留下什么没办完的事，就调 sol_astr_compact 把早前的
        记录收一收。还在聊同一件事就先放着。]
```

**三个数必须都给**。只写「当前/压缩线」模型会把压缩线当成容量上限——用掉 105k 明明还很宽裕，写成 `105000/98400` 却像是已经溢出了，模型会莫名其妙地开始惜字如金。

模型仍然可能就是不调。台账会记录**「够格却没调」**（`not_called`），于是：

```
触发率 = 调用次数 / (调用次数 + not_called 次数)
```

这个数是判断插件该不该继续用的首要依据，面板顶部直接显示。

## 先跑影子模式

`dry_run` 默认开着，全流程照跑但不调摘要、不改写历史。台账在 `data/plugin_data/astrbot_plugin_astrsol/ledger.jsonl`：

| outcome | 含义 |
|---|---|
| `not_called` | 上下文够格了，但模型这一轮没调工具 |
| `too_small` | 模型调了，但归档段不够大 |
| `dry_run` | 影子模式，本该压缩 |
| `empty_summary` | 摘要模型返回空，零改写 |
| `compacted` | 真的压了 |

先看触发率和归档段分布，看明白了再把 `dry_run` 关掉。

## 工作方式

压缩按整轮切分：最近 `keep_recent` 的整轮原样保留，当前这轮永远保留，更早的交给摘要模型压成一段替换回去。`messages[0]` 的 system prompt 绝不动。上一次压缩产生的摘要在下次压缩时会被一并重摘，所以摘要不会越积越多。

状态行放在用户消息**末尾**而不是 system prompt，是为了不动上游的前缀缓存；它会跟着历史落盘，**不要想着把它摘掉**，摘掉反而会让下一轮的前缀和缓存对不上。

## 已知限制

- **依赖模型自觉调用**。需要支持 function calling。它不调 = 功能不触发，台账会记 `not_called`；乱调 = 旧内容变成摘要而非丢失，保留段原样不动，归档段不够大时会被直接挡回去。
- **人格白名单会屏蔽本工具**，面板会检测并告警。
- **WebChat 会显示工具调用过程**，它无视 `show_tool_use_status`。其他平台默认不可见。
- **压缩耗时叠加在回复之前**。非流式下用户干等摘要，流式下正文已发出、卡的是收尾。靠便宜摘要模型控制，超时由 AstrBot 的 `tool_call_timeout` 兜底，超时即零改写。
- **价目是 OpenRouter 的官方牌价**。走聚合渠道时实付可能不同；公式是比值、货币单位会约掉，所以只要两个模型的溢价比例接近，结论仍然成立。
- **别的插件停掉事件会导致整轮不落盘**，压缩结果跟着一起丢。
- **压缩后的第一轮缓存要重建**，这是这套机制生来就要付的钱，已计入公式。
